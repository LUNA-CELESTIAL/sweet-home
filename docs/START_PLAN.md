# 作り始め方 — 順番が大事

原則: 仕事から逆順に作る (2026-11-16 のタスクファースト)。
オーケストレーター/基盤の形から入らない。一番重い動画は最後。
旧ボットは動画のみ構成で動かしたまま並行し、切り替えは最後に一度だけ。

## Step 0: 凍結と置き場 (今日できる)
- 旧 chibi_bot にはもう手を入れない (足跡として残す)
- 新しい置き場を決める: 新リポジトリ + 専用作業場。コードはゼロからルナが書く
- REBUILD_NOTES を v0 仕様として確定する (未決定は最小限: 書き手の決め方、サイトへの受け渡し経路)

## Step 1: 日記だけの試作 (投稿なし・動画なし・熱ゼロ)
一番の軸を一番安く検証する。
- 材料: 旧 #lunachannel の今日の投稿 (Discord 読み取り入口で取得できる実物)
- やること: 締めの書き手1人が出来事プールを1ページの日記に編む試作を、ここで数日分作ってみる
- 合格基準:
  - ログの転載ではなく、誰かの目で見た1日になっている
  - 翌朝の一言に、昨日の日記の何かを自然に使える
  - 読んで「Discord でこんなことしてるんだ」がサイト訪問者にも伝わる文面になっている
- これが通らなければ、ボットを作る前に日記の型を直す

## Step 2: 会話セッションの試作 (Discord には出さない)
- 種 (出来事) → 場の組み立て1回 → 1人1台詞の逐次生成 → 3〜5往復で終了、までを通す
- 間隔 (2〜10分) はタイマーのダミーで再現し、塊の見え方を確認する
- 合格基準: 前の発言を受けている / 人格で注目点が違う / エッセイに戻っていない

## Step 3: スケジューラ (ここで初めて基盤)
- 1つのキュー、種類ごとの最低間隔、1日の予算 (動画5〜6本 / 会話3塊)、熱ガード
- 最初はダミージョブで「間隔と予算が守られること」だけを検証する

## Step 4: 当番テキスト → 音声 → 動画の順に実ジョブを載せる
- 朝・夜当番: まずテキスト投稿のみで数日回す
- 安定したら VOICEVOX、最後に動画 (5秒×2) を載せる
- ゆる Vlog (3〜4本) はその後。サイトへの日記受け渡しもこの段階で接続する

## Step 5: 切り替え
- 新ボットが 当番+会話+日記 を1日完走できたら、旧ボットを止めて切り替える
- 切り替え後1週間は改善しない (動いたら触らない原則)。様子見は読み取りだけ

## やらないこと (最初は)
- RSS の再実装
- サイトの大幅改修 (日記カード追加のみ)
- 訪問者向け招待リンクの発行 (日記が窓として機能してから別途)
