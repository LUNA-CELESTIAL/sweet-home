# 設計メモ: #vlog の逆転設計

状態: 設計メモ（2026-11-25 記録、るる提案）。同日、計画承認を経て **最小実装済み**（src/vlog.py）：#作業場 の「vlog：」リクエスト → プレビュー（#作業場）→ 上映メモ → #vlog 投稿＋姉妹3人の感想（テキスト経路）。姉妹が動画を「見る」方法は、初期形は上映メモ経由で確定。ビジョン経路は実機のモデル確認後に差し込み可能。

同日、**見せ方と編集を追加実装**（るる決定）：リクエストに「テーマ：」「見どころ：」（表の顔。#vlog の上映投稿に出す。意図は監督の手元メモとして感想の材料にだけ使う）と、上映メモの「編集：」行で指示する編集ステップ（状態は pending → previewed → memo_ready → **edited** → screened）。編集の語彙と適用は src/edit.py：そのまま／トリミング：A-B／速度：X／ループ（行って戻る）／表紙：T（編集後の時間軸で取る）、適用順は固定（トリミング→速度→ループ）。編集失敗は failed で閉じて #vlog には出さない。却下は「vlog却下：理由」で最も古い上映前テイクを閉じる。

## 旧形（やらない）

RSS を Ollama に調べさせ、Ollama が話題を選び・要約し・プロンプトを作って動画化する。過負荷の元だった形で、sweet-home では取り戻さないと決めたもの。

## 新形（るる提案）

- プロンプトはメイン側ルナが考え、「テーマ／プロンプト／参照画像／意図（何を見せたいか）」が揃った完成状態で渡す。Ollama には調査もプロンプト作成もさせない。
- ローカルは動画生成だけを行い、完成した動画を #vlog に上げる。
- Ollama（姉妹たち）の役割はその逆で、動画ができてから感想を言う側。作る側ではなく、見る側・受け取る側。
- 感想は各人のペルソナで短く。感想同士の違い（同じ動画を見てどう受け取るかがズレること）自体が素材になる。
- この感想は、その日のリビングの話題や日記の材料になり得る（既存の循環：朝の共有→その日のリビング、に自然に乗る形）。

## 未決の技術点（設計時に確認）

姉妹が動画を「どう見るか」— 抽出フレームを渡す／メイン側ルナが内容の短い説明を添える／ビジョン対応モデルを使う、のどれにするかは最初の1本で確かめる。

## 置き分け

- #作業場 ＝ テスト・裏側（フレームテスト等の実験）
- #vlog ＝ ルナが監督した完成動画＋姉妹の感想
